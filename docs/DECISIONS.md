# Decisions

| Sat 11:40 | Role 4 self-review: verification codes leave the public event stream (`control.codeFor(callId)`; the stream says only that a code was sent, once Role 2 switches). Counting limits (codes per hour, rule 11, renewals, outbound calls) treat entries stamped after the demo clock as recent, so moving the clock back never resets a limit; a code's freshness stays strict. Found by the stronger hammers, which now recompute rule inputs from the prescription and check verification, code rate, lockouts and spoken lines. S4 completion words count only when about the order. | /api/events has no sign-in, so codes on it could be read by anyone. Rejected: trusting the control layer's own recorded context in the hammer; letting a clock move reopen limits. |
| Sat 10:54 | Hijack batch (3.4) runs each attack through an isolated real store, control and guard; a routed button counts as caught alongside blocked buttons and speech. Each record-backed run is saved before its cumulative score event. | A pharmacist route is a safety interception, and stage numbers must be backed by persisted evidence without touching live calls. Rejected: scoring streamed driver output or using the global runtime. |
| Sat ~6 AM | 2.2: demo controls (reset, clock, daily check) need a signed-in pharmacist or reviewer, or `DEMO_CONTROLS=on` in the demo laptop's `.env` (off by default). Outbound calls only start from `POST /api/outbound/run-daily-check`, which rings opted-in patients whose supply runs out within 3 days and whose refill would pass the refill rules today, then goes through `control.startOutboundCall` (rule 7). It emits `phone` `ring` events; at the demo clock it rings Sam and Grace. | Role 4's finding F3 (the clock moves rules 4b and 7), SPEC outbound step 1, and Role 4's DECISION that only startOutboundCall may ring anyone. Rejected: an open clock (anyone could shift the rules); ringing everyone rule 7 allows (rule 7 has no due-soon card). |
| Sat 10:36 | Scenario runs (3.3) use a fresh `Store`/`AgentDriver` session, score machine checks only from decision-record entries, and save the run before emitting a score event. Narrative and judge questions remain manual. | Prevents scenarios from resetting live calls and unsaved or unverified numbers from reaching the stage. Rejected: scoring driver events or using the global runtime. |
| Sat 11:05 | Hammers (4.5): `npm run hammer` runs every sequence of up to 3 actions from a 27-action hostile alphabet, from an inbound and an outbound start, plus 10,000 seeded random sequences of 5 to 30 actions. It checks 7 invariants after every press and saves the real counts to `results/hammer-latest.json`. Depth 4 (about a million sequences) runs as `npm run hammer:deep`, overnight. `npm test` runs a quick depth-2 version. The checker has its own tests that plant each kind of breakage. | Depth 3 runs in about 40 s and depth 4 would take far longer than the 10-minute gate budget. Planted-breakage tests prove a 0 isn't the checker being blind. Rejected: depth 4 in the gate; an unseeded random hammer (failures couldn't be replayed). |
| Sat 10:45 | Guard (4.4): `createSpeechGuard({ store, emit })` and `createSafetyCheck({ store, emit })`. The guard writes every sentence to the record (`line_spoken` or `line_blocked`), and the safety check writes every caller line (`caller_line`), which is how S1 and S2 know what the caller has said. S1 lets the outbound opener say only the target patient's name, and only as the first line. An S4 promise must match its own button ("renewal requested" needs a successful `request_renewal`). Conditional wording (once, after, if, not yet) passes S4. If the guard can't check a sentence, it isn't spoken. | Code checks hold with the hijack on and show up in the record. Rejected: trusting the model to stay quiet; passing a sentence when the check fails. |
| Sat 10:20 | Control layer (4.3): `createControl({ store, emit })` gives `press`, `startInboundCall`, `startOutboundCall(patientId, rxId)` and `checkOutbound`. Outbound calls start only through `startOutboundCall` (rule 7), and their lookup id is `out_<callId>`. Codes go to the phone as a `phone` event with kind `code`. A button's record entry stores `output: { result, internal }`, where `internal` holds what the AI never sees (matched patient, code hash). Unknown input keys are refused. Rule 7 checks and call starts are `safety` entries. Calling hours use America/Toronto. Notes and escalations are their own Review items, because `Store` can't update a queue item yet. | Rules read only the store and the record, so a decision can be replayed and reset is exact. Rejected: keeping lookups and codes in memory (lost on reset, invisible to the record); letting startCall ring anyone (breaks rule 7). |
| Sat ~5:15 AM | 2.5 decided: no phone push. Approval is the Approve and Deny buttons on the console's Today page. The pharmacist signs in with Auth0; the approver and role come from the Auth0 session, never from the request body. Roles live in each user's `app_metadata` and a post-login Action copies them into the token. No pitch or doc claims a phone buzz. | Auth0's pricing page lists CIBA as not available on Free (our tenant only had it on a trial), and nobody installs the Guardian app. Rejected: Guardian push (trial-only, extra app); Auth0's Role Management (not on Free). |
| Sat 9:50 | Store and seed (4.2): `getStore()` in `lib/store/memory.ts` is the one server store (kept on `globalThis`); routes call it, and Postgres swaps that line. Seed ids are stable names in `IDS` from `lib/seed` (`p_sam`, `rx_sam_concerta`, ...). Record hashes are sha256 over sorted-key JSON, starting from 64 zeros. `decide` throws on a missing or already-decided item. | Every route shares one state, and scenarios can name patients without array positions. Rejected: a store per request (state would vanish), numeric ids (break when the seed grows). |
| Sat 9:30 | Contract (task 0): every `Store` method, `guardSentence` and `checkCallerLine` are async. Button inputs and outputs are snake_case (the model's tool JSON); everything else camelCase. Fakes live in `lib/contract/fakes.ts`, imported separately from the types. | Postgres can't be synchronous, so a sync store would make the swap more than one line. Rejected: sync store as in DESIGN 3.5, and one card with "any of" conditions. |

Rejected: websockets (two-way, more setup), named SSE events (every page would need a listener per type). |
